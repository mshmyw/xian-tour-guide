# 秦俑小导游

给**识字很少的老人**和**4 岁左右的小朋友**用的西安兵马俑、丽山园语音导览。

纯 HTML + CSS + 原生 JavaScript 静态 PWA：无框架、无 Node.js、无构建，直接部署到 GitHub Pages，可离线播放。

本文件同时是使用说明和开发维护文档，项目不再保留重复的历史审查稿。

**当前状态**：9 个地点 / 22 段讲解 / 约 9.7 分钟 ｜ 项目 **1.1 MB** / 29 个文件（其中上线 23 个）｜ `sw.js` 缓存版本 `v28`
**自检**：`node tools/verify.js`（结构、引用、时长）｜ `node tools/smoke-node.js`（44 项交互仿真，不需要浏览器）

### 已知问题（有意保留的取舍）

1. **安卓的手机语音可能依赖联网** —— 景区信号差时，18 段手机语音有概率不发声（iPhone 无此问题）。补救：给该段补录音。
2. **手机没装中文语音包** —— 自动把该段文字显示在屏幕上，并提示「这台手机没有中文语音」。
3. **WebP 需 iOS 14 / 安卓 5 以上** —— 更老的设备图片不显示，退化为纯深色背景（文字、按钮、音频正常）。
4. **字幕是"大致同步"** —— 没有逐句时间轴，按字数比例估算；换真人录音后可补时间码。
5. **隐藏的「进园须知」里含独有信息** —— 时间底线（最晚 14:30 开始看兵马俑、16:30 去丽山园）、安检禁带、厕所在哪，目前应用里没有其他段落提到；它的素材也已从仓库清掉（恢复见上文）。

## 一、设计定稿

这个 App 的主体是**声音**，屏幕只保留当前地点、播放操作、本段进度和跟读字幕。

当前内容为 **9 个地点、22 段讲解、约 9.7 分钟**。打开后直接进入「出发前」，没有额外操作教学。

发音是**混合方案**：4 段关键录音 + 18 段手机自带语音（原因见「音频」一节）。

- 一屏只有一个地点、一张大图。
- 底部只有三个主要操作：`◀`、黄色播放/暂停键、`▶`。
- 第一次只按一次「开始听」；同一地点的故事随后**自动连续播放**。
- 一个地点播完，自动进入下一处，不需要任何操作。
- 点左右箭头换地点，换完自动播放；也可以在图上左右滑动（备用操作）。
- 每个地点最后自动播放小朋友彩蛋（`🎁`）；播完有星星动画。
- 主界面只保留**右上角**一个 `☰` 按钮（**地点抽屉**）；放右上角是为了避开顶部居中的地点名与图标。
- **画面本身就是个巨大的播放/暂停按钮**：孩子点哪儿都能停、能播。
- 主界面不放容易和“换地点”混淆的段落小箭头；想重听某段时在地点抽屉里直接点。
- 每听完一个地点，它在抽屉里的图标会**变大变亮**（像收集到一张贴纸）。
- 有录音的段落播录音；没有录音（讲解段）或录音打不开时，自动改用手机自带中文语音朗读。
- 播放时按句显示大字幕，帮助老人听清、家长跟读；暂停后自动隐藏，不挤占主画面。
- 左下角离线状态只有在**全部录音和场景图确认已缓存**后才变绿；下载失败时抽屉底部会出现「重新下载离线内容」。

### 临时隐藏某一节

不想展示某个地点、又不想删内容（比如「进园须知」），把它加进 `data.js` 顶层的 `skip` 数组即可：

```javascript
skip: ['entry'],   // 暂时不展示「进园须知」；清空数组就恢复
```

隐藏地点的**素材已从仓库里清掉**（省空间），恢复需要两步：

```bash
# 1) 清空 data.js 里的 skip
skip: [],

# 2) 重新生成它的音频和封面图（几秒钟）
node tools/make_audio_node.js --missing     # 补音频
python3 tools/make_images.py                # 需要的话重画封面占位图
```

`node tools/verify.js` 只检查**展示中**地点的素材，隐藏地点缺文件不算错误。

## 二、家人怎么用

1. **出发前一晚**：连 Wi-Fi 打开一次页面，App 会自动下载全部内容。等左下角小圆点变成**绿色**，才表示 4 段录音和 9 张场景图都已缓存，可以离线使用。
2. **加到主屏幕**：iPhone 用 Safari → 分享 → 添加到主屏幕；安卓用 Chrome → 安装应用。
3. **进园后**：点一次黄色「开始听」。**必须点这一次**，手机才允许出声。
4. **之后不用管**：一段接一段自动播放；想暂停就点同一个按钮。
5. **换地点**：点 ◀ ▶ 箭头；或在图上左右划一下。
6. **想直接跳到某处**：点右上角 `☰`。抽屉里按「出发前 / 兵马俑 / 丽山园 / 看完后」分组列出全部 9 处，每个地点下面还列出**它有几段、每段讲什么**，点哪一段就从哪一段开始讲。
7. **想重听某一段**：在抽屉里点对应的段落，点一次就会收起抽屉并开始播放。

## 四、本地预览

**必须用 http 服务打开，不要直接双击 `index.html`。**

原因：双击打开时浏览器把本地脚本当成跨域，会拦掉 `data.js`，页面只能显示一句错误提示（应用会直接告诉你"请用网址打开"）。

```bash
cd xian-tour-guide
python3 -m http.server 8080
# 电脑上打开 http://localhost:8080
# 手机连同一 Wi-Fi： http://<电脑内网IP>:8080   （查内网 IP： ipconfig getifaddr en0）
```

Service Worker（离线能力）也要求 http/https，`file://` 下不会注册。完整部署见下一节。

## 五、部署到 GitHub Pages

### 一条命令生成「干净的可部署仓库」

开发目录里还有 `tools/`、README、审查文档等**不需要上线**的东西。用脚本把它们排除掉：

```bash
cd xian-tour-guide
bash tools/deploy.sh ~/Desktop/xian-tour-guide-repo
```

脚本会做四件事：复制必需文件 → 检查有没有绝对路径（会导致子路径 404）→ 核对 `data.js` 引用的图片和音频是否齐全 → 打印体积。

### 推上去

```bash
cd ~/Desktop/xian-tour-guide-repo
git init && git add -A && git commit -m "feat: 秦俑小导游 v1"
git remote add origin git@github.com:<你的用户名>/xian-tour-guide.git
git push -u origin main
```

### 打开 Pages

仓库 `Settings → Pages → Source: Deploy from a branch → main / (root) → Save`。
等 1–2 分钟，得到：

```text
https://<你的用户名>.github.io/xian-tour-guide/
```

### 部署后第一次必须做的事

1. **用手机打开这个网址**（iPhone 用 Safari，安卓用 Chrome）。
2. 点一次「开始听」，确认有声音；再点右上角 `☰`，看最下面是不是「📶 全部已下载，可以离线用」。
3. 看到「全部已下载，可以离线用」后，再**添加到主屏幕**（iPhone：分享 → 添加到主屏幕；安卓：菜单 → 安装应用）。
4. 出发前在酒店 Wi-Fi 下等左下角圆点变绿；不需要手动把每段都播一遍。如果下载失败，抽屉底部会出现「重新下载离线内容」。

> 微信里打开不能加到主屏幕，会提示「在浏览器中打开」。

### 为什么不用直接从开发目录 push

开发目录位于你的工作区大仓库里（`.git` 在工作区根目录），在那儿 push 会把开发工具一起推上去。用 `deploy.sh` 生成独立仓库最干净；当前会生成 23 个运行文件、约 1.1 MB。

## 六、修改内容

所有内容集中在 `data.js`。一个地点长这样：

```javascript
{
  id: 'bmy-1',                     // 决定 images/bmy-1-v2.webp 与 audio/bmy-1-*.mp3
  emoji: '🕳️',                     // 大图标：不识字的人靠它认地方
  name: '一号坑',
  phase: 'bmy',                    // 抽屉分组
  tracks: [
    {
      id: 1,                       // 段号；有录音时也是音频文件名
      title: '两千年前的军队，还站在原地',   // 会先念出来（正文已包含时不重复念）
      dur: 29,                     // 秒；录音段填实际时长，手机语音段按实测语速估算
      text: '走进一号坑大厅，欢迎来到兵马俑……', // 正文；朗读稿 = 标题 + 正文（去重后）
      // audio: ['audio/bmy-1-1.mp3']   // ← 不写 audio 就用手机自带语音朗读
      // label: '走进一号坑大厅',       // 只给屏幕看的备注（一般不用，方位提示直接写进 text）
    }
    // …更多段；路线提示并入最后一段，不单独占音频
  ],
  kids: {                          // 每处结尾自动播的童声彩蛋（手机语音，音调会调高）
    id: 1,
    title: '小朋友，陶俑其实是空心的',
    text: '……我们来玩个游戏：你也站得直直的，看能站多久？'
  }
}
```

### 改完内容后的标准三步

```bash
node tools/make_audio_node.js                # 1. 重新合成音频
node tools/make_audio_node.js --missing      #    或者：只补 audio/ 里缺的那几段
node tools/make_audio_node.js prep-1         #    或者：只重录指定的段
node tools/verify.js                         # 2. 自检（引用、阶段、孤儿文件、dur）
node tools/smoke-node.js                     # 3. 冒烟测试（点击流程是否还正常）
# 最后把 sw.js 的 VERSION 加一，再 push
```

> 音频生成用 Node 直接调用 `say` / `ffmpeg`（`tools/make_audio_node.js`），不经 shell——
> 段落 id 里的连字符在 shell 里曾被误解析（`prep-1` 变成 `rep-1`），所以不要再用 bash 循环生成。

### 音频：4 段录音 + 18 段手机语音

**判断规则只有一条**：写了 `audio` 就播录音，没写就用手机自带中文语音。

| 用什么 | 哪些段落 | 为什么 |
|---|---|---|
| **录音文件**（4 段，约 700 KB） | 出发前、进园须知 ×2（已隐藏）、收尾 | 有家人名字、电话、时间底线、安检规则——错一个字就出问题，必须有确定的声音 |
| **手机语音**（18 段） | 三个坑、丽山园、百戏俑、铜车马、封土（含童声彩蛋） | 讲解型内容，改词零成本；省下十几个音频文件 |

手机语音参数（`app.js`）：`rate 0.8`（放慢，老人好跟）、`pitch 1.18`（音调略高，更亲切、不那么机械）；
童声彩蛋 `pitch 1.35`（一听就知道是"小朋友频道"）。音色优先挑「婷婷 / 美佳 / 晓晓」，否则任意中文音色。

> **代价（已确认接受）**：安卓的手机语音**可能依赖联网**，景区信号差时有概率不发声；
> 极少数没装中文语音包的手机会完全没声音（此时会自动把文字显示在屏幕上）。
> 想更稳，就给某几段补录音：把 `audio: ['audio/xxx.mp3']` 加回该段落，再跑一次 `node tools/make_audio_node.js xxx`。

录音规格：Tingting「慢速温和」档（语速 155 + 去齿音 + 人声提亮 + 压限 + 响度归一化 -17 LUFS），
64 kbps / 22.05 kHz / 单声道，段首留 150ms、段尾留 300ms。

`dur` 字段：录音段填**音频真实秒数**（`verify.js` 会核对）；手机语音段按实测语速 **3.54 字/秒**（含标题与停顿）估算。

换更好的声音：`VOICE=Tingting RATE=145 node tools/make_audio_node.js`（更慢更亲切），
或直接用剪映「文本朗读」导出 MP3 覆盖 `audio/`（`node tools/make_audio_node.js --dump > 朗读稿.txt` 可导出朗读稿）。

### 字幕

- 字幕默认开启，只在播放时显示，暂停后隐藏。
- 整段讲解会按标点切成短句，再根据每句字数和音频真实时长估算切换时机。
- 现有 MP3 没有逐句时间轴，因此字幕是“大致同步”，不保证逐字精准。如果以后换成真人录音，可在数据里补逐句时间码。
- 录音失败、改用系统中文语音时，同样会显示字幕和估算进度。

#### 觉得声音太机械怎么办（三档，从省事到最好）

| 办法 | 效果 | 成本 |
|---|---|---|
| **1. 下载系统高级语音** | 明显更自然 | 免费。系统设置 → 辅助功能 → 朗读内容 → 系统声音 → 管理声音 → 中文 → 下载「婷婷（高级）」，然后 `node tools/make_audio_node.js` 重录 |
| **2. 换音色 / 调语速** | 好一点 | 免费。`RATE=172 node tools/make_audio_node.js`（默认 155 慢速；RATE 越大越快）或 `VOICE=Meijia` 换音色 |
| **3. 用剪映 / 豆包的「文本朗读」** | 最接近真人（可选童声、温柔女声等） | 免费；导出 MP3 后按 `audio/<地点id>-<段号>.mp3` 覆盖，并在该段落加回 `audio` 字段 |

第 3 种的省事做法：先把朗读稿一键导出成文本，再粘到剪映里批量配音。

```bash
node tools/make_audio_node.js --dump > 朗读稿.txt  # 每行：文件名 + 该段要念的话
```

### 图片

- 命名：`images/<地点id>-v2.webp`（每个展示地点一张）。
- 规格：**长边 900px、WebP q74、单张 60–80 KB**（`verify.js` 超过 150 KB 会提示）。
- 为什么用 WebP：同样清晰度下比 JPEG 小约 60%。实测 10 张从 1845 KB 压到 **672 KB**。
- 图片在应用里是**压暗的背景**（透明度约 42–55% + 渐变遮罩），这个分辨率完全够用。
- 兼容性：iOS 14 / 安卓 5 以上支持 WebP；更老的设备图片不显示（退化成纯深色背景，文字和按钮仍正常）。


### 更新离线缓存

改完页面、图片、音频或讲解词，把 `sw.js` 顶部版本号加一：

```javascript
const VERSION = '26';
```

`sw.js` 先预缓存页面壳文件；页面启动后会根据 `data.js` 自动把当前所有录音和图片发给 Service Worker 下载，**新增音频不必再往手写清单里加**。

音频走「**在线优先、离线回缓存**」：改了录音，家人刷新一次就能听到新版，不会被旧缓存卡住。

## 七、离线规则

`sw.js` 第一次联网打开时先缓存页面外壳，然后按 `data.js` 的实际引用逐个下载全部录音和场景图（当前 4 段录音 + 9 张图，共约 0.7 MB + 0.7 MB）。全部成功后才显示绿点；失败时会保留已下好的内容，并在抽屉里提供重试。

注意：

- **首次必须联网**，并且要等左下角小圆点变绿再出发。
- iPhone 必须由用户先点一次「开始听」，网页才允许出声。
- 清理浏览器网站数据会同时清掉离线内容，需要重新联网打开。
- 手机侧边静音键打开时网页可能无声，App 会在画面上提示关掉静音或调大音量。
- GitHub Pages 默认 HTTPS，满足 PWA 要求。

## 九、维护原则

后续优先做**更好的语音和实拍照片**，不要增加账号、复杂菜单、文字答题或多层设置。
对这批用户而言，「少按一次、少读一句」比多一个功能更重要。
