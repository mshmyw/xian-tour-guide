# 秦俑小导游

给**识字很少的老人**和**4 岁左右的小朋友**用的西安兵马俑、丽山园语音导览。

纯 HTML + CSS + 原生 JavaScript 静态 PWA：无框架、无 Node.js、无构建，直接部署到 GitHub Pages，可离线播放。

本文件同时是使用说明和开发维护文档，项目不再保留重复的历史审查稿。

**当前状态**：9 个地点 / **9 段讲解（每个地点一段 mp3）** / 约 22.6 分钟 ｜ 上线 **30 个文件 / 7.2 MB**（音频 6.5 MB + 图片 0.6 MB）｜ `sw.js` 缓存版本 `v51`
**自检**：`node tools/verify.js`（结构、引用、时长、语速、`?v=` 与版本号一致性）｜ `node tools/smoke-node.js`（81 项交互仿真：点击 / 滑动 / 键盘 / 拖进度条 / 讲完那一刻的状态，不需要浏览器）｜ `bash tools/seek-check.sh`（真实浏览器验进度条拖动）

### 有意保留：`sw.js`（离线能力）

`sw.js` 只负责"**没网时也能打开页面**"，不负责"有没有声音"。保留它的理由：景区坑里确实没信号，
而家人关掉浏览器（或手机清理后台）后再打开，没有它就会白屏。它的代价已压到最小——
音频走"在线优先"、页面导航"网络优先 + 3 秒超时"，所以有网时刷新就能拿到新版。

去掉也行：会少 259 行（`sw.js`）+ 约 45 行（`app.js`）+ 4 个界面元素，代价是失去"离线可靠打开页面"。

### 已知问题（有意保留的取舍）

1. **音频体积 6.5 MB** —— 全 mp3 的代价。第一次需要在有 Wi-Fi 的地方缓存完（欢迎卡会显示进度），之后完全离线。相比"用手机语音省流量"，更看重的是**景区里一定有声音、进度条能拖**。
2. **录音放不出来时只有文字，没有声音** —— 弹红框说明原因，并把整段文字铺在屏幕上，点播放键可重试。这是删掉 TTS 后**有意接受**的取舍：宁可让用户看到"没声音了，我写给你看"，也不要一个突兀的机器人声。
3. **WebP 需 iOS 14 / 安卓 5 以上** —— 更老的设备图片不显示，退化为纯深色背景（文字、按钮、音频正常）。
4. **字幕是"大致同步"** —— 没有逐句时间轴，按字数比例估算。现在是全 mp3，**理论上可以补逐句时间码做到精准**，属于可做未做。
5. **隐藏的「进园须知」里含独有信息** —— 时间底线（最晚 14:30 开始看兵马俑、16:30 去丽山园）、安检禁带、厕所在哪，目前应用里没有其他段落提到。`skip` 里去掉 `entry` 即可恢复，音频 `audio/entry.mp3` 已经生成好了。

## 一、设计定稿

这个 App 的主体是**声音**，屏幕只保留当前地点、播放操作、本段进度和跟读字幕。

当前内容为 **9 个地点、9 段讲解、约 22.6 分钟**（每个地点一段，合并成一条完整动线）。打开后直接进入「出发前」，没有额外操作教学。

9 段**全部是 mp3 录音**，不依赖设备语音，进度条每一段都能拖。

- 一屏只有一个地点、一张大图。
- 底部只有三个主要操作：`◀`、黄色播放/暂停键、`▶`。
- 引导卡**整张卡任意位置都能点**（不要求点中按钮）；点一次就开始讲这一站。
- **一个地点播完就停下，不自动跳到下一处。** 现场是要走路的：这站听完，人得先挪到下一个坑，
  再决定什么时候听。自动跳过去会把人拽着跑（"我还没看完呢，怎么已经讲到下一个坑了"）。
- **停下后屏幕上没有任何引导文案。** 这一条是上面那条的必然结论：既然"自动跳"被否掉是因为
  不该拽着人跑，那屏幕上再挂一句 `✅ 点 ▶ 去一号坑` 加一个**一直晃**的箭头，就只是把自动跳
  换成了视觉版的拽人。景区里该看的是坑，不是手机。现在讲完那一刻只有四件事发生，全都不要求动作：
  1. 声音停了；
  2. 撒一次星星（2.2 秒，庆祝，不指向任何操作）；
  3. 中间大按钮从 `Ⅱ` 变回 `▶`；提示回到中性的「👂 听故事」；
  4. 右侧箭头**轻晃两下就停**（`1.6s × 2`，不是 `infinite`；最后一站箭头禁用时不晃）。

  > 曾经在屏幕上放过 `✅ 讲完了 · 点右边 ▶ 或滑一下，去「三号坑」`，后来缩短到
  > `✅ 点 ▶ 去一号坑`（实测 421px → 218px，因为 320px 的屏只有 280px 可用），
  > 最后**整个删掉**。留下的判断是：讲完了这件事由上面第 1~4 条说清楚；
  > 下一站叫什么，录音结尾的转场句本来就会念（"看完后，我们去三号坑"）；
  > "怎么继续"由家人当面教一次（见「二、家人怎么用」），不该靠屏上一句话承担。
  > 别再往回加 —— `smoke-node.js` 会逐站断言这个位置必须停在「👂 听故事」。
- 点左右箭头换地点，换完自动播放；也可以在图上左右滑动（备用操作）。
- 每个地点是**一整段**连续讲解（原来拆成 1~3 小段 + 童声彩蛋，已合并）；播完有星星动画。
- 抽屉顶部有**进度导览（路线带）**：把 9 站排成一条线，**灰=没去过 / 点亮=去过 / 金圈=现在这一站**，连接线随进度变绿；每个节点都能点，直接跳过去。
  路线带上**不放文字**，抽屉里也不再单列一行进度数字——图形本身已经说明一切，避免多处口径不一致。
- 主界面只保留**右上角**一个 `☰` 按钮（**地点抽屉**）；放右上角是为了避开顶部居中的地点名与图标。
- **画面本身就是个巨大的播放/暂停按钮**：孩子点哪儿都能停、能播。一站讲完后点它 = **从头再讲一遍本站**
  （`▶` 就该是"再放一遍"）；要往下走用右侧 `▶` 箭头或左右滑动（换地点那一套操作）。
- 主界面不放容易和“换地点”混淆的段落小箭头；每站只有一段，想重听**直接点中间的播放键**（讲完后再点就是重播），
  也可以在地点抽屉里点那一站（要跳到别的站时用它）。
- 每听完一个地点，它在抽屉里的图标会**变大变亮**（像收集到一张贴纸）。
  抽屉里**一个地点就是一张卡**：图标 + 地名 + 这段讲什么 + 状态点（`▶` 当前 / `✅` 听过 / `·` 没听），整张卡可点，点一下直接开讲。
- 9 段全部是 mp3 录音；万一某个文件加载失败，弹红框并把整段文字铺在屏幕上，点播放键可重试。
- 播放时按句显示大字幕，帮助老人听清、家长跟读；**暂停时字幕保留**（只变淡），方便停下来读完。
- 底部进度条**可拖动**（每段都是 mp3，都有时间轴）。
- 离线是否就绪不再靠小圆点，而是**文字说明**：欢迎卡和抽屉底部都会写「✅ 已下载完，没信号也能听」；下载失败时抽屉底部出现「重新下载离线内容」。

### 临时隐藏某一节

不想展示某个地点、又不想删内容（比如「进园须知」），把它加进 `data.js` 顶层的 `skip` 数组即可：

```javascript
skip: ['entry'],   // 暂时不展示「进园须知」；清空数组就恢复
```

隐藏地点的**封面图已从仓库里清掉**（省空间；音频留着 —— `audio/entry.mp3` 还在，恢复时不用重录）。
恢复要做两件事：

```bash
# 1) 清空 data.js 里的 skip
skip: [],

# 2) 补回它的封面图 images/<地点id>-v2.webp（长边 900px、q74 WebP、150KB 以内）
#    注意：原先的 tools/make_images.py 已不在仓库里，现在需要自备一张，
#    或先用任意深色占位图顶上（verify.js 只要求文件存在、体积别超标）

# 万一音频也不在了（换机器、清理过仓库），再补音频：
node tools/make_audio_node.js --missing
```

`node tools/verify.js` 只检查**展示中**地点的素材，隐藏地点缺文件不算错误。

## 六、修改内容

所有内容集中在 `data.js`。一个地点长这样：

```javascript
{
  id: 'bmy-1',                     // 决定 images/bmy-1-v2.webp 与 audio/bmy-1.mp3
  emoji: '🕳️',                     // 大图标：不识字的人靠它认地方
  name: '一号坑',
  phase: 'bmy',                    // 抽屉分组
  tracks: [
    {
      id: 1,                       // 每个地点只有一段，固定写 1
      title: '两千年前的军队，还站在原地',   // 抽屉卡片上的副标题；也会先念出来（正文已包含时不重复念）
      dur: 99,                     // 秒；= mp3 实测时长，用 tools/fill_dur.js 自动回填
      text: '走进一号坑大厅，欢迎来到兵马俑……', // 正文；朗读稿 = 标题 + 正文（标题已在正文里就只念一遍）
      audio: ['audio/bmy-1.mp3']   // 写了 audio 就播这个录音；没写（正常不会有）只会铺文字，不出声
    }
  ]
}
```

> `label` 字段（抬头指引）已经删掉：方位提示本来就写在 `text` 里，见「变更记录 · 上一轮」。
> `audio` 是数组是为将来留多格式 fallback，现在 9 段都只放一个 mp3。

**每个地点只有一段。** 原来的写法是拆成 1~3 小段、外加一个 `kids` 童声彩蛋（界面上一号坑显示 1~4）。合并的原因：

- 音频文件从 24 个降到 10 个，离线缓存和 `sw.js` 都更简单；
- 每个地点 = 一个 mp3 = 一条完整时间轴，**进度条每一段都能拖**（手机语音没有时间轴，拖不动）；
- 讲解本来就是一走动线（"走进大厅……往前走到栏杆边……慢慢往坑的后方看"），拆开反而在段落之间制造了断点。

合并时注意：**童声内容按语义插在转场句之前**。比如一号坑的「看完后，我们去三号坑。」原本在正文末尾，如果直接拼接童声会变成"我们走吧……嘘，告诉你一个秘密"，读起来很跳。现在的顺序是「……拼回来的。嘘，告诉你一个秘密……一直站着。看完后，我们去三号坑。」

### 改完内容后的标准四步

```bash
node tools/make_audio_node.js bmy-1            # 1. 重录改动的段（不带参数 = 全部重录）
node tools/make_audio_node.js --missing        #    或者：只补 audio/ 里缺的那几段
node tools/fill_dur.js                         # 2. 用 ffprobe 实测时长回填 dur
node tools/verify.js                           # 3. 自检（引用、阶段、孤儿文件、dur、语速、版本号）
node tools/smoke-node.js                       # 4. 冒烟测试（点击流程是否还正常）
# 5. 把 sw.js 的 VERSION 和 index.html 里三处 ?v= 同时加一，再 push
#    （两处必须一起改：漏了 ?v= 时家人刷新后先拿到的还是旧样式/旧脚本；verify.js 会核对）
```

> 音频生成用 Node 直接调用 `say` / `ffmpeg`（`tools/make_audio_node.js`），不经 shell——
> 段落 id 里的连字符在 shell 里曾被误解析（`prep-1` 变成 `rep-1`），所以不要再用 bash 循环生成。

### 音频：9 段 mp3，全部录音

每个地点一段 `audio/<地点id>.mp3`，共 9 段、约 22.6 分钟（1357 秒）、**6.5 MB**（40 kbps 单声道；隐藏的进园须知另有 0.26 MB，打包时不含）。

**判断规则**：写了 `audio` 就播这个文件。9 段全都配了 `audio`；某一节没配时，页面会把文字铺出来并提示，
**不再退回手机自带语音**——`speechSynthesis` 已经整个移除。

> 为什么不留着「4 段录音 + 18 段手机语音」的混合方案：安卓的系统语音**可能依赖联网**，
> 景区信号差时有概率不发声。对一个"站在坑边必须马上有声音"的场景，
> 这个不确定性比 4 MB 流量更贵。既然后来全部改成了 mp3，TTS 这套就整个删掉了。

录音规格：Tingting「慢速温和」档（语速 155 + 去齿音 + 人声提亮 + 压限 + 响度归一化 -17 LUFS），
**40 kbps** / 22.05 kHz / 单声道，段首留 150ms、段尾留 300ms。

#### 为什么 40 kbps 够用

拿一段真实讲解（78 秒）走**完全相同的后期链**生成无损参考，再按 5 档码率编码，用 FFT 对比长时平均频谱：

| 码率 | 文件 | 低通截止 | 9 kHz 以下 | 停顿底噪 |
|---|---|---|---|---|
| 64k | 617 KB | ~9.5 kHz | 基准 | −24.3 dB |
| 48k | 463 KB | ~9.7 kHz | 与 64k 差 ±1 dB | −22.8 dB |
| **40k** | **386 KB** | **~9.5 kHz** | **与 64k 差 ±1 dB** | **−21.8 dB** |
| 32k | 309 KB | ~8.5 kHz | **9 kHz 以上被砍掉（−67 dB）** | −19.7 dB |
| 24k | 231 KB | ~5.5 kHz | 7 kHz 以上全无 | — |

**64 / 48 / 40 三档在 9 kHz 以下完全一致**，差异都在 ±1 dB（属噪声级）；分水岭在 32 kbps，
它把 9 kHz 以上整个砍掉，听感会发闷。所以 40 kbps 是"再往下就要听出来"的临界点。

两个旁证：① 64 kbps 的**立体声**播客 = 每声道 32 kbps，我们单声道 40 kbps 比它还宽；
② 播放场景是景区户外的手机喇叭（本身 10 kHz 以上就衰减，环境噪声也大），这点底噪差异听不出来。

码率已做成可配置项，想回退：`BITRATE=64k node tools/make_audio_node.js`。

`dur` 必须等于 mp3 实测秒数。**它不只是显示用的**：音频元数据还没加载完时，进度条的量程会回退到 `dur`
（`seekTotalSeconds()`），所以 `dur` 错了，拖动就会落到错误的位置。`verify.js` 会核对两者，差超过 2 秒就提示。
不用手填：

```bash
node tools/fill_dur.js          # 实测后写回 data.js
node tools/fill_dur.js --check  # 只看差异，不改文件
```

换更好的声音：`VOICE=Tingting RATE=145 node tools/make_audio_node.js`（更慢更亲切），
或直接用剪映「文本朗读」导出 MP3 覆盖 `audio/`（`node tools/make_audio_node.js --dump > 朗读稿.txt` 可导出朗读稿）。

#### 进度条全程可拖

手机自带语音（`speechSynthesis`）**没有可定位的时间轴**，只能从头念到尾——这就是以前"没录音的段落拖不动"的原因。
全 mp3 之后每段都有时间轴，**9 站全部可拖**，`.seek-off` 与「这段拖不动」的提示也一并删掉了。

拖动时先暂停（指头和声音对不上就先停住），松手后**按原状态恢复**：原来在播就接着播，原来暂停就停在拖到的位置。
「松手」绑在 `document` 上而不是滑块上——手指滑出滑块范围时 `pointerup` 不会在滑块上触发，
绑在滑块上的话 `seekEnd` 永远不执行，表现就是"松手又弹回原处"。

两种验证方式：

```bash
node tools/smoke-node.js        # 假 DOM：9 站逐个拖 + 暂停态拖动 + 无禁用残留
bash tools/seek-check.sh        # 真浏览器：复用 index.html，逐站报"拖到 50% 是否真落在 50%"
```

> 为什么要两个：假 DOM 里 `currentTime` 只是个普通属性，赋值必定成功；
> 真实 `<audio>` 在元数据没加载完时赋值会被忽略甚至抛错。后者只能真浏览器验。

### 字幕

- 字幕默认开启：播放时按句切换；**暂停时不消失，只变淡**（老人可以停下来读完、跟家人讨论）。
- 整段讲解会按标点切成短句，再根据每句字数和音频真实时长估算切换时机。
  切句结果按段缓存，不会每 250ms 重算一遍。
- 现有 MP3 没有逐句时间轴，因此字幕是“大致同步”，不保证逐字精准。如果以后换成真人录音，可在数据里补逐句时间码。
- 录音打不开时字幕会**常显整段文字**（`.no-speech`），让人至少能看字，点播放键可重试。

#### 觉得声音太机械怎么办（三档，从省事到最好）

| 办法 | 效果 | 成本 |
|---|---|---|
| **1. 下载系统高级语音** | 明显更自然 | 免费。系统设置 → 辅助功能 → 朗读内容 → 系统声音 → 管理声音 → 中文 → 下载「婷婷（高级）」，然后 `node tools/make_audio_node.js` 重录 |
| **2. 换音色 / 调语速** | 好一点 | 免费。`RATE=172 node tools/make_audio_node.js`（默认 155 慢速；RATE 越大越快）或 `VOICE=Meijia` 换音色 |
| **3. 用剪映 / 豆包的「文本朗读」** | 最接近真人（可选温柔女声等） | 免费；导出 MP3 后按 `audio/<地点id>.mp3` 覆盖即可（文件名不用改） |

第 3 种的省事做法：先把朗读稿一键导出成文本，再粘到剪映里批量配音。

```bash
node tools/make_audio_node.js --dump > 朗读稿.txt  # 每行：文件名 + 该段要念的话
```

### 图片

- 命名：`images/<地点id>-v2.webp`（每个展示地点一张）。
- 规格：**长边 900px、WebP q74、单张 60–80 KB**（`verify.js` 超过 150 KB 会提示）。
- 为什么用 WebP：同样清晰度下比 JPEG 小约 60%。实测 10 张从 1845 KB 压到 **672 KB**。
- 图片在应用里是**压暗的背景**（透明度约 42–55% + 渐变遮罩），这个分辨率完全够用。
- 兼容性：iOS 14 / 安卓 5 以上支持 WebP；更老的设备图片不显示（退化成纯深色背景，文字和按钮仍正常）。


### 更新离线缓存

改完页面、图片、音频或讲解词，把 `sw.js` 顶部版本号加一，**同时把 `index.html` 里三处 `?v=` 改成同一个数**：

```javascript
const VERSION = 'v51';      // ← sw.js
```

```html
<link rel="stylesheet" href="styles.css?v=51">   <!-- ← index.html：styles.css / data.js / app.js 三处 -->
```

两处必须一起改：`?v=` 决定家人刷新时先拿到新版还是旧缓存，`VERSION` 决定 Service Worker 是否清理旧缓存。
`node tools/verify.js` 会核对这两个数是否一致，不一致直接报错，不用靠人记。

`sw.js` 先预缓存页面壳文件；页面启动后会根据 `data.js` 自动把当前所有录音和图片发给 Service Worker 下载，**新增音频不必再往手写清单里加**。

音频走「**在线优先、离线回缓存**」：改了录音，家人刷新一次就能听到新版，不会被旧缓存卡住。

## 七、离线规则

`sw.js` 第一次联网打开时先缓存页面外壳，然后按 `data.js` 的实际引用逐个下载全部录音和场景图（当前 9 段录音 + 9 张图，共约 6.5 MB + 0.6 MB）。全部成功后才显示绿点；失败时会保留已下好的内容，并在抽屉里提供重试。

注意：

- **首次必须联网**，并且要等欢迎卡（或抽屉底部）出现「✅ 已下载完，没信号也能听」再出发。
- iPhone 必须由用户先点一次「开始听」，网页才允许出声。
- 清理浏览器网站数据会同时清掉离线内容，需要重新联网打开。
- 手机侧边静音键打开时网页可能无声，App 会在画面上提示关掉静音或调大音量。
- GitHub Pages 默认 HTTPS，满足 PWA 要求。
